# Firmware F1.3.8dev5 — the card converts web images

This development build adds a picture service for Apple programs. The
A2MONO browser uses it. It contains everything in
[F1.3.8dev4](F1.3.8dev4.md), with the same FPGA image.

## Picture service

Until now A2MONO pulled each encoded image to the Apple in pieces of 504
bytes and decoded it on the 6502. It refused images above 64 KiB after it
had pulled the first 64 KiB. Now the card does the work.

- **Request.** An Apple program sets the new IMAGE flag in a START command
  and gives a box (width and height). Capability bit `$20` of the
  descriptor reports the service.
- **Formats.** PNG, JPEG (baseline and progressive) and GIF (first frame).
  The encoded image can have up to 8 MiB, and up to 4096 x 4096 and
  4,194,304 pixels.
- **Conversion.** The card shrinks the image to the box with its
  proportions, and does not enlarge it. It dithers to 1 bit with error
  diffusion. Transparent pixels go on white paper, or on black paper when
  the opaque part of the image is light.
- **Result.** The Apple reads the width, the height and then rows that are
  the bytes of a 560-column monochrome double hi-res row. A picture of
  546 x 240 pixels has 18,724 bytes, which is 38 reads.
- **Repaint.** During a picture request the screen repaints 10 times each
  second, as for a file download.

`README_HTTP_SMARTPORT_PROTOCOL.md` has the protocol.

The JPEG and GIF decoders come from `stb_image` 2.34 (public domain), a new
file in `third_party/stb/`. PNG uses lodepng, which the firmware already
had.

Limits:

- The card decodes an image in one step in its main loop. For a large
  image that step can take some tenths of a second. During it the card
  does not serve other foreground work, such as SmartPort disk calls and
  the menu. Nobody has measured this time on a card.
- `stb_image` is not hardened against hostile files. The card checks the
  declared size before a decode, but a malformed JPEG or GIF from a web
  site could still make the card stop. PNG does not use `stb_image`.
- WebP and SVG are not supported.

## Build and validation

Only the ARM code changes. This package uses the FPGA build
`20261120T190553Z-fea5c6e9-full` of F1.3.8dev1 again. Packaging does not
rebuild the FPGA.

- Setup WNS **+0.160 ns**, hold **+0.047 ns**, pulse width **+0.265 ns**.
- No failing endpoints. Route, bus skew, and checked constraint bounds
  pass, with zero missing constraint objects.
- The run used a +0.000 ns export gate. The package check requires
  +0.020 ns.

Checks:

- `test_net_image.py` runs the conversion on a PC: the size rules, no
  enlargement, transparency, the gray level of the dither, the padding
  bits, a GIF, and bad input.
- `test_net_service.py` runs the protocol: the flag rules, a body that
  arrives in parts, the rows that the Apple reads, a file that is not an
  image, and an HTTP error.
- `test_online_update_main.py` checks the 10 Hz repaint during a picture
  request.
- The A2MONO test `mono_arm_images.py` (in the appletini-software
  repository) runs the 6502 browser against a model of this service: one
  request for each picture, no decoder file load, and no request when the
  page scrolls back.
- The two pictures of appletini.org convert on a PC: the 453 KiB board
  picture becomes 433 x 240 pixels.

The package contains a new XSA-derived platform, FSBL, and both ARM
cores. Golden Boot stays at **B2.0.6**. This package has no Golden update.

## Hardware test

Nobody has flashed or tested this image on a card. Install `FIRMWARE.BIN`
through the normal firmware updater, and use the A2MONO disk of the same
date.

- A2MONO: open `https://appletini.org`, press **I**, and note the time
  until both pictures show. Scroll down and up: the pictures must come
  back without a load message.
- During a picture load, check that a disk in use and the sound do not
  stop for a noticeable time.
- A2LYNX and STARFALL rankings: they do not use the new flag and must work
  as before.
- The tests of F1.3.8dev1 to F1.3.8dev4 still apply.
