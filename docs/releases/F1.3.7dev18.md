# Firmware F1.3.7dev18 — SSI-263 pitch glide

The SSI-263 speech chips now glide their pitch as the SC-02 prototype
circuit does. This applies to transitioned inflection (function 3) on both
Phasor sockets.

- The pitch moves toward the target in bits I10 to I6 at a constant slope.
  Bits 10 to 3 of the pitch word move one count per
  128 × (8 − slope) × (16 − rate) clock cycles. Slope is I5 to I3.
- I11 and I2 to I0 take effect at once.
- The glide scales with the speech rate, as on the real chip.
- The first transitioned phoneme after power-on starts at its target.

The earlier model reached each target within about 2 ms, so slow glides
sounded like steps. The new rate equals the rate that the ssi263-speech
project measured on a real chip in 426 glides. Immediate inflection
(functions 1 and 2), phoneme timing, formants and levels do not change.

This build also contains everything in F1.3.7dev17, including the VSYNC
alignment fix.

## Build and validation

This package uses the full FPGA build `20261118T193414Z-b63b74b4-full`.
Packaging does not rebuild the FPGA.

- Setup WNS **+0.014 ns**, hold **+0.056 ns**, pulse width **+0.265 ns**.
- No failing endpoints. Route, bus skew, and checked constraint bounds
  pass, with zero missing constraint objects.
- The run used a +0.000 ns export gate. The package check requires
  +0.014 ns, which Henri accepted for this build. This is less than the
  +0.050 ns gate of the standard full-build helper.
- The build used the Explore placer and a 0.260 ns implementation margin.
  The repository profile still selects the Default placer.
- Six full runs finished. Five failed, by 0.008 to 0.251 ns, on the DIR
  pad paths or the vTW logic. No failing path was in the glide logic.
  `TIMING_ATTEMPTS.json` lists all runs.

Checks of the glide:

- A Vivado simulation bench measures the clock count between pitch
  changes for all 16 rates and 8 slopes, up and down: 3,077 checks pass.
- The host model passes the same closed-form check (768 intervals), and
  the host render, listening, tract, source, control and Phasor card tests
  pass.
- The Verilator suites that compare the RTL with the host model sample by
  sample did not run, because Verilator is not installed on the build
  machine.
- `test_ssi263_attack_audit.py` fails, as it did before this change. Its
  trace tool and the renderer use different output gains.

The package contains a new XSA-derived platform, FSBL, and both ARM
cores. Golden Boot stays at **B2.0.6**. This package has no Golden update.

## Hardware test

Nobody has flashed or tested this image on a card. Install `FIRMWARE.BIN`
through the normal firmware updater. Then listen to speech that uses
transitioned inflection,
and compare it with a real Mockingboard or Phasor. Also do the VSYNC
monitor check from F1.3.7dev17.
