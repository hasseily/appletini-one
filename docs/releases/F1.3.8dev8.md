# Firmware F1.3.8dev8 — image sizes from CSS

This development build makes the page service read the image sizes that a
page gives in CSS. It contains everything in [F1.3.8dev7](F1.3.8dev7.md),
with the same FPGA image. TINIBROWSER of 21 November 2026 (11:24) needs no
change for it.

## Page service

Most pages give the size of an image in a style sheet, not in `width` and
`height` attributes. The card now reads three sources:

- the `style` attribute of the image;
- `<style>` blocks in the page;
- up to three linked style sheets (`<link rel="stylesheet">`), which the
  card fetches after the HTML.

From these it takes `width`, `height`, `max-width` and `max-height`, and
writes the result as `w=N` and `h=N` on the image.

- **Units.** px, em and rem (16 pixels), and for widths percent and vw of
  the 546-pixel screen width.
- **Selectors.** The last part must select the image by the tag `img`, a
  class or an id, with up to two classes. One part before it can name an
  ancestor, as in `.hero img`. The card ignores rules with pseudo-classes,
  attribute selectors, `+` and `~`.
- **Order.** A rule with more weight wins (id, then class, then tag); for
  equal weight the later rule wins. The `style` attribute wins over rules,
  and rules win over the `width` and `height` attributes.
- **@media.** A block applies when its `max-width` and `min-width`
  conditions include a 546-pixel screen. Print sheets are left out.

On appletini.org (page and `site.css` fetched on 21 November 2026) the
small wordmark in the menu gets `h=24`, and the large wordmark and the
board picture get `w=546`.

Limits:

- `clamp()`, `calc()`, `min()`, `max()`, `auto`, heights in percent and
  CSS variables are not read. Such a size is left out, and the image shows
  at its natural size.
- A percent width is a percent of the screen, not of the parent element.
- Each linked sheet is one more HTTPS request, so a page with three sheets
  loads more slowly. A sheet has 8 seconds; all sheets of a page share
  1 MiB. A sheet that fails is left out.
- The card stores at most 256 size rules for a page.
- Only image sizes come from CSS. Colours, fonts, positions and
  `display: none` in style sheets are not used.

## Build and validation

Only the ARM code changes. This package uses the FPGA build
`20261120T190553Z-fea5c6e9-full` of F1.3.8dev1 again. Packaging does not
rebuild the FPGA.

- Setup WNS **+0.160 ns**, hold **+0.047 ns**, pulse width **+0.265 ns**.
- No failing endpoints. Route, bus skew, and checked constraint bounds
  pass, with zero missing constraint objects.
- The run used a +0.000 ns export gate. The package check requires
  +0.020 ns.

Checks:

- `test_net_page.py` has one new case: a linked sheet, a `<style>` block
  with an ancestor part and a media rule, and a `style` attribute.
- `test_net_service.py` has one new case: the request for a linked sheet
  after the page, and the page data in the descriptor after it.

The package contains a new XSA-derived platform, FSBL, and both ARM
cores. Golden Boot stays at **B2.0.6**. This package has no Golden update.

## Hardware test

Nobody has flashed or tested this image on a card. Install `FIRMWARE.BIN`
through the normal firmware updater.

- Open `https://appletini.org`: the wordmark in the menu line is small
  (24 pixels high). The board picture stays 433 x 240, because 240 pixels
  is the height limit of a picture.
- Note the time for the page to show, compared with F1.3.8dev7.
- The tests of F1.3.8dev1 to F1.3.8dev7 still apply.
