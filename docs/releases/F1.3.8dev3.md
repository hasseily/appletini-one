# Firmware F1.3.8dev3 — faster downloads

This development build makes downloads faster for the CoGS game browser and
for Apple programs that use the HTTP interface (A2LYNX). It contains
everything in [F1.3.8dev2](F1.3.8dev2.md), with the same FPGA image.

## Network

Until now only the firmware updater had fast transfer settings. All other
clients moved at most 4 KiB for each pass of the main loop, and the screen
repaint stopped that loop for about 20 ms, 25 to 60 times each second. Now
one set of transfer settings serves all clients.

| Item | F1.3.8dev2 | This build |
|---|---|---|
| Receive memory of the TCP socket in the W5100S | 4 KiB | 8 KiB |
| TCP acknowledge | delayed | immediate |
| One socket read | 512 bytes | up to 4 KiB |
| Body buffer in the ARM | 4 KiB | 128 KiB |
| One SD write of a download | up to 4 KiB | 32 KiB |
| Screen repaint during a transfer | each frame | 10 times each second |
| TLS handshake | full, each request | the server can resume the last session |

- **W5100S socket.** While a request owns the Ethernet chip, the Apple cannot
  reach it, so the TCP socket takes all 8 KiB of receive memory and sends
  each acknowledge at once. The firmware restores the normal 4/2/1/1 KiB
  layout before the Apple gets the chip back. The updater did this since
  F1.3.5.
- **Socket reads.** A poll reads for a 2 ms slice. The first read of a poll
  always runs; a later read does not start after the slice is over. The
  updater keeps its longer read chain.
- **Body buffer.** The network keeps reading while a decrypted TLS record
  goes to SD. Before, it stopped for four loop passes for each 16 KiB record.
- **SD writes.** A download goes to SD in pieces of 32 KiB. Only the last
  piece of a file is smaller.
- **Repaint.** The repaint rate drops to 10 Hz while the CoGS browser loads
  its catalog or downloads a disk, and while a file download that an Apple
  program started goes to SD. A key or button press still repaints at once.
  During such a file download the Apple picture also updates at 10 Hz. Page
  loads by Apple programs keep the normal rate.
- **TLS session.** The firmware keeps the last verified TLS session for
  10 minutes and offers it to the same host and port. A server that still
  has that session skips the key exchange and the certificate transfer.
  `a2cogs.com` resumes sessions (5 of 5 in a test from a PC with the same
  cipher suite); GitHub does not. The CoGS catalog needs 36 requests to
  `a2cogs.com`, so 35 of them can resume.
- **CoGS screen.** The download line shows the average rate in KiB/s.

`README_HTTP_SMARTPORT_PROTOCOL.md` has the new ring size and the 32 KiB
step of the written field.

Limits:

- Nobody has measured the download rate on a card, before or after this
  change. The causes come from the source code and from October card
  records of the main loop.
- A device 2 to 3 ms from the test network answers TCP for far servers. On
  such a network the small W5100S window costs little. On a direct path the
  larger window and the immediate acknowledge matter more.
- The Apple still reads a page through SmartPort calls of 504 bytes. That
  limits a page load by an Apple program, not this firmware.
- GitHub needs a full handshake for each request, and a GitHub download
  needs two requests because of its redirect.

## Build and validation

Only the ARM code changes. This package uses the FPGA build
`20261120T190553Z-fea5c6e9-full` of F1.3.8dev1 again. Packaging does not
rebuild the FPGA.

- Setup WNS **+0.160 ns**, hold **+0.047 ns**, pulse width **+0.265 ns**.
- No failing endpoints. Route, bus skew, and checked constraint bounds
  pass, with zero missing constraint objects.
- The run used a +0.000 ns export gate. The package check requires
  +0.020 ns.

Checks:

- `test_http_update_throughput.py` runs the real HTTP engine against a
  model of the Ethernet chip. It checks the 8 KiB socket and the immediate
  acknowledge for all owners, the 128 KiB ring with backpressure, and that a
  second socket read does not start after the slice.
- `test_http_download.py` checks that a 200,003-byte body reaches the file
  in six pieces of 32 KiB and one last piece, with the same bytes.
- `test_online_update_main.py` checks the 10 Hz repaint limit for the CoGS
  browser and for a file download, the repaint at once on input, and the
  full repaint when the transfer ends.
- `test_cogs_service.py` and `test_cogs_menu.py` check the rate value and
  the rate text.
- `test_http_tls_resume.py --live` uses the firmware's TLS library settings
  and call order from a PC. Against `a2cogs.com` the first handshake needed
  1,044 steps with 1,017 pauses for key-exchange work; the second one
  resumed the session in 15 steps with no such pause. No host test runs
  this path inside the HTTP service itself.
- Of the 62 host tests that read a changed file, 49 pass. The other 13 fail
  in the same way on an untouched copy of commit fea5c6e, or need the lab
  TLS peer, which was not running: `test_ad8088_card`,
  `test_config_profiles`, `test_disk2_standard`,
  `test_gamepad_binding_config`, `test_golden_about_menu`,
  `test_golden_menu_runtime`, `test_http_mobile`, `test_http_tls_handshake`,
  `test_onee_vtw_runtime`, `test_phasor_ssi_ui`,
  `test_resolution_config_menu`, `test_video_smoothing_config` and
  `test_vtw_turbo_frontend`.

The package contains a new XSA-derived platform, FSBL, and both ARM
cores. Golden Boot stays at **B2.0.6**. This package has no Golden update.

## Hardware test

Nobody has flashed or tested this image on a card. Install `FIRMWARE.BIN`
through the normal firmware updater.

- CoGS: open **Ethernet > CoGS games** after a reboot and time the catalog
  load. Download one small disk and one 32 MB collection, and note the
  KiB/s value on the screen. Start each downloaded disk.
- A2LYNX: load some pages, then download a file to SD and compare it with
  the same file from a PC.
- Ethernet from the Apple: after a download, run a program that uses the
  Uthernet II (for example an IP65 program) to check that the chip is back
  in its normal state.
- Online update check from the menu: it must still find the release.
- The video, speech and bus tests of F1.3.8dev1 and F1.3.8dev2 still apply.
