# Firmware F1.3.7dev20 — ONE//e keyboard acts like one latch

In ONE//e mode, a new key now replaces keys that the Apple program has
not read yet.

A real //e has one keyboard latch and no queue, so a new key replaces an
unread one. The ONE//e keyboard kept every key in order. A program that
reads the keyboard rarely then had to work through all earlier keys
before it saw the newest one.

The Phasor disk's "Speech Parameter Adjust" screen showed this. It reads
one key per spoken sentence. With F1.3.7dev19, Escape after two other
keys took three sentences to act.

- When a new key arrives while older keys still wait in the card's
  queues, the card drops the waiting keys and keeps the new one.
- Keys that arrive in the same USB report are all kept.
- The key already in the Apple latch stays. The card cannot replace it
  without an FPGA change. So a new key acts after one earlier key at most.
- A held key still does not build a backlog of repeats (F1.3.7dev19).

The cost is the same as on a real //e: type-ahead is lost when a program
is slow to read keys. Programs that read the keyboard often, such as the
BASIC prompt, are not affected.

This build contains everything in F1.3.7dev19, including the SSI-263
pitch glide and the VSYNC alignment fix.

## Build and validation

Only the ARM code changed: `ps_sources/frontend/onee_input_service.c`
and the version header. This package reuses the FPGA image of
F1.3.7dev18, build `20261118T193414Z-b63b74b4-full`, byte for byte.
No new FPGA run was made.

- FPGA timing is that of F1.3.7dev18: setup WNS **+0.014 ns**, hold
  **+0.056 ns**, pulse width **+0.265 ns**, no failing endpoints.
- The FPGA run was built from commit `b63b74b` with local changes. The
  ARM code was built from commit `3932b80` with local changes.
  `SOURCE_FREEZE.json` records both commits. Its hashes show that the HDL
  and Tcl build inputs equal those of F1.3.7dev18.
- `scripts/test_onee_input_service.py` has a new case: a new key with
  another key waiting flushes the FIFO and then goes in, and a new key
  with nothing waiting causes no flush. This test and the ONE//e config
  menu tests pass.

The package contains a new XSA-derived platform, FSBL, and both ARM
cores. Golden Boot stays at **B2.0.6**. This package has no Golden update.

## Hardware test

Nobody has flashed or tested this image on a card. Install `FIRMWARE.BIN`
through the normal firmware updater. In ONE//e mode, start the Phasor
disk and open "Speech Parameter Adjust". Tap an arrow key twice and then
Escape. Escape must act within two sentences. Also check that fast
typing at the BASIC prompt loses no characters.
