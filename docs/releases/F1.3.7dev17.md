# Firmware F1.3.7dev17 — VSYNC alignment

Both VSYNC edges now align with the start of HSYNC. The timing generator
uses the next active-video row at that edge to keep the intended porch
and pulse lengths. At 1080p, both edges move 192 pixel clocks earlier.

The active NTSC 1080p frame still has 2200 pixels per line and 1126 lines
at 148.5 MHz (about 59.947 Hz). Active PAL keeps its 1123-line total.
DE, framebuffer reads, pixel clocks, and the frame-total policy stay the
same, so this image tests the sync-phase change on its own.

This build uses the current F1.3.7dev16 branch with the VSYNC fix. It
includes the branch's PC Transporter, IIgs, and Phasor changes. It is not
based on the customer's F1.3.6 source. Compared with the dev16 package,
only the video timing generator and its regression differ in HDL. The
only ARM source change is the firmware version header.

## Build and validation

This package uses the full FPGA build
`20261118T172122Z-b63b74b4-full`. Packaging does not rebuild the FPGA.

- Setup WNS **+0.043 ns**, hold **+0.057 ns**, pulse width **+0.265 ns**.
- No failing endpoints. Route, bus skew, and checked constraint bounds
  pass, with zero missing constraint objects.
- The run used a +0.000 ns export gate. A separate package check requires
  +0.020 ns. This is less than the +0.050 ns gate of the standard
  full-build helper. The original manifest stays unchanged.
- The build used the Explore placer and a 0.275 ns implementation margin.
  The repository profile still selects the Default placer. The HDL and all
  other scripts match the frozen source.
- The bitstream, XSA, and checkpoint match their recorded hashes. The XSA
  contains that bitstream.

The FPGA is near its timing limit with this source. Of 15 completed full
runs on Nov 17 and 18, only two met the export gate (+0.005 ns and
+0.043 ns).
The DIR_D pad path and the vTW logic caused most failures.
`TIMING_ATTEMPTS.json` lists the Nov 18 runs. The Nov 17 runs are in
`build/vsync-f137dev17/TIMING_ATTEMPTS.json`.

The RTL regression checks both VSYNC edges, their positions, and one
assertion and deassertion per frame. All six modes pass at both 50 Hz and
60 Hz, with extra active-genlock cases for NTSC 1126 and PAL 1123 lines.
The old RTL fails both edge checks. Mode-control, framebuffer
mode/restart, pixel-mask, and mask-configuration simulations also pass.

The package contains a new XSA-derived platform, FSBL, and both ARM
cores. Golden Boot stays at **B2.0.6**. This package has no Golden update.

## Hardware test

The customer reported flicker and a leftward horizontal wrap on an ASUS
PA32QCV with F1.3.6, an NTSC Apple, and direct HDMI. Nobody has flashed or
tested this image on a board or monitor yet. Install `FIRMWARE.BIN`
through the normal firmware updater. Then examine the picture on that
monitor in each mode.
