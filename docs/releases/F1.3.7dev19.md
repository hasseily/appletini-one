# Firmware F1.3.7dev19 — ONE//e key repeat

In ONE//e mode, a held key no longer builds a backlog of repeats.

A real //e has one keyboard latch and no queue. A held key strobes the
same latch again, so a program that reads the keyboard rarely sees one
key. The ONE//e keyboard queued each repeat instead, up to 40 keys. A
program that reads one key per long action then worked through all of
them after the key was released.

The Phasor disk's "Speech Parameter Adjust" screen showed this. It reads
one key per spoken sentence. A key held for two seconds queued about 15
repeats, and the screen then ignored new keys, Escape included, for 15
sentences.

The card now queues a repeat only when no earlier key still waits. Real
key presses still queue as before, so fast typing is not lost. At most
two repeats can be pending.

This build contains everything in F1.3.7dev18, including the SSI-263
pitch glide and the VSYNC alignment fix.

## Build and validation

Only the ARM code changed: `ps_sources/frontend/onee_input_service.c`
and the version header. This package reuses the FPGA image of
F1.3.7dev18, build `20261118T193414Z-b63b74b4-full`, byte for byte.
No new FPGA run was made.

- FPGA timing is that of F1.3.7dev18: setup WNS **+0.014 ns**, hold
  **+0.056 ns**, pulse width **+0.265 ns**, no failing endpoints.
- The FPGA run was built from commit `b63b74b` with local changes. The
  ARM code was built from commit `3932b80` with local changes.
  `SOURCE_FREEZE.json` records both commits. Its hashes show that the HDL
  and Tcl build inputs equal those of F1.3.7dev18.
- `scripts/test_onee_input_service.py` has a new case: 40 repeat periods
  with a key still waiting queue nothing, and one repeat follows when the
  key is read. This test and the input bridge simulation pass.

The package contains a new XSA-derived platform, FSBL, and both ARM
cores. Golden Boot stays at **B2.0.6**. This package has no Golden update.

## Hardware test

Nobody has flashed or tested this image on a card. Install `FIRMWARE.BIN`
through the normal firmware updater. In ONE//e mode, start the Phasor
disk, open "Speech Parameter Adjust", and hold an arrow key for a few
seconds. After release, the screen must obey the next key within about
two sentences. Also check that normal typing and key repeat at the BASIC
prompt work as before.
