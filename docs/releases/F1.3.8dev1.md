# Firmware F1.3.8dev1 — SSI-263A amplitude table

This development build changes the level of 12 SSI-263 phonemes. It also
changes how the FPGA build treats the two Apple direction pads.

## Speech

The speech parameter table is the SSI-263A file `ssi263a.bin` again, byte
for byte. From F1.2.5-d2 to F1.3.7 the table had 16 amplitude targets from a
read of an SSI-263P die. A recording of two chips marked SSI 263 AP showed
that those chips have the SSI-263A values.

These 12 phonemes become louder. No other phoneme changes.

| Phoneme | Code | Voice amplitude, old to new | Noise amplitude, old to new |
|---|---:|---|---|
| L1 | `$21` | 8 to 15 | same |
| Z | `$2F` | 1 to 2 | 10 to 15 |
| J | `$31` | 1 to 2 | 10 to 15 |
| SCH | `$32` | same | 6 to 9 |
| V | `$33` | 3 to 6 | 4 to 8 |
| F | `$34` | same | 4 to 8 |
| THV | `$35` | 1 to 2 | 2 to 4 |
| TH | `$36` | same | 2 to 6 |
| M | `$37` | 10 to 15 | same |
| N | `$38` | 8 to 15 | same |
| NG | `$39` | 4 to 8 | same |
| LB | `$3F` | 8 to 15 | same |

The host model rendered the phoneme sweep of the calibration disk with each
table. Against the real chip, over the 55 phonemes that sound, the RMS level
error went from 3.64 dB to 1.27 dB. The worst error went from 12.6 dB (TH)
to 2.9 dB. See
[the ROM format note](../SSI263_SC02_ROM_FORMAT.md).

Formants, pitch, timing and all other phonemes do not change. This build
also contains everything in F1.3.7.

## FPGA build: source registers for the direction pads

`a2fpga_dir_a` and `a2fpga_dir_d` have a 10 ns register-to-pad limit. About
25 registers all over the fabric feed them: machine identity, policy, ONE//e
isolation and IIgs ownership. In ten full runs of this source, a direction
path was the worst path each time, by 0.09 to 0.45 ns.

The build now runs `scripts/replicate_direction_sources.tcl` before
placement. For each of those registers it adds a twin flip-flop with the
same D, CE, reset and clock nets and the same INIT. Only the load pins
inside the direction-pad logic move to the twin. The placer can then put
the twin near the pads.

- Each twin equals its original in every clock cycle. No logic function,
  state or bus phase changes. The RTL does not change.
- The hook reads the netlist back and stops the build if a twin differs
  from its original in type, INIT, any input net or any load.
- The pinned LUTs and the raw PHI0 release path do not move.
- The routed design has 29 twins. The timing manifest records the count
  and the hash of the hook.

## Build and validation

This package uses the full FPGA build `20261120T190553Z-fea5c6e9-full`.
Packaging does not rebuild the FPGA.

- Setup WNS **+0.160 ns**, hold **+0.047 ns**, pulse width **+0.265 ns**.
- No failing endpoints. Route, bus skew, and checked constraint bounds
  pass, with zero missing constraint objects.
- `a2fpga_dir_d` has +0.274 ns and `a2fpga_dir_a` has +0.284 ns. The PHI0
  release path has +0.472 ns.
- The run used a +0.000 ns export gate. The package check requires
  +0.020 ns.
- The build used the Explore placer and a 0.260 ns implementation margin.
  The repository profile still selects the Default placer.
- Before the hook existed, ten full runs failed and four were stopped. With
  the hook, the first run passed and the second failed by 0.166 ns on a vTW
  shadow RAM write path; its direction paths were at -0.056 and -0.010 ns.
  Two more runs were in progress when this package was made.
  `TIMING_ATTEMPTS.json` lists all runs.

Checks:

- `test_ssi263_die_rom.py` checks the table against the SSI-263P die bit
  matrix, the 16 listed differences, the `ssi263a.bin` hash and the host
  table mirror.
- The host data, control, source, tract, render, listening, capture and
  Phasor card tests pass.
- The build tooling tests pass: run profile, manifest format, margin hooks,
  packaging and the 25 vTW benches.
- The Verilator suites that compare the RTL with the host model did not
  run, because Verilator is not installed on the build machine. The RTL and
  the host model read the same table file.
- `test_ssi263_attack_audit.py` and the source-list check in
  `test_ssi263_control_core.py` fail, as they did before this change.
- No simulation covers the twin registers. They exist only in the placed
  netlist. The check is the read-back in the hook.

The package contains a new XSA-derived platform, FSBL, and both ARM
cores. Golden Boot stays at **B2.0.6**. This package has no Golden update.

## Hardware test

Nobody has flashed or tested this image on a card. Install `FIRMWARE.BIN`
through the normal firmware updater.

- Speech: listen to the 12 phonemes above and compare them with a real
  SSI-263. TH, M, N and NG show the largest change. S (`$30`) and L (`$20`)
  do not change and can serve as a reference.
- Bus: the direction pads have new source registers. Check boot and disk
  access on a //e, a II+ and a IIgs, and a change to ONE//e and back.
